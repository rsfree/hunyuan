问题根因处置
4K 交付 3877×2160
比请求宽 37 px		 imageMogr2/thumbnail/!WxHr 是 cover 语义：上游 16:9 实际出的是 2240×1248（1.7949，不是 1.7778），按高贴合后宽自然溢出 已修 改链式 thumbnail/!WxHr|imageMogr2/gravity/center/cut/WxH，实测精确到 3840×2160 / 2560×1440
21:9 请求悄悄变成 16:9 上游没有 21:9 槽位，_size_to_ratio() 按对数距离映射到最近的 16:9 未改 这是能力边界，不报错是兼容性选择；已在响应 upscale.exact=false 与 note 里写明
踩坑记录（都做了实测验证）：
  • thumbnail/!WxHr/cut/WxH（用斜杠连写）会被 整体忽略并静默返回原图 —— CI 的链式分隔符必须是 |
  • 裁切只在「请求比例 ≈ 上游槽位比例（≤2%）」时做；否则硬裁会削掉主体（实测横图硬裁成 1080×1920 丢掉左右大幅画面）
  • 本地保留 4K-exact.png 作证：sips 读取为 3840 × 2160
